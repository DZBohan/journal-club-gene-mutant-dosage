# 文献解读 HTML 标准

## 内容结构

解读是让读者理解文章的教材，不是逐段翻译或扩写摘要。默认中文，可按需产生英文对等版本。

1. 文章信息、原文链接、一句话核心问题与答案。
2. 背景 introduction：领域已知、未解决问题、为什么现有方法不足。
3. 阅读地图：数据、核心方法、验证、应用、下游模型分别在哪。
4. 概念与缩写词表：先用中文直觉解释，再给英文术语和严格定义。
5. 数据与研究设计：来源、筛选、数量、测量平台、分组、对照、训练/测试和重复层级。
6. 方法分步：输入、操作、输出、目的；必要公式旁解释每个变量、单位、方向与假设。
7. 按研究问题解读 figure panels，含关键补充图，而不只按页码贴图。
8. 核心结果表：结论、数据、来源 panel、证据强度、不能推出什么。
9. 批判性讨论：偏倚、混杂、统计功效、泛化、反例、机制与关联的边界。
10. 本组价值与可执行后续实验，明确是建议而非论文结果。
11. 组会提纲、三个讨论问题、take-home messages。
12. 来源、版本、已知争议与未解决问题。

论文类型不适用的条目可调整，但要保留背景、问题、方法、具体结果和批判性判断。

## 每个 figure panel 的必答卡片

- 这张图回答什么问题？
- 用了哪些样本、实验或模型？
- 横纵轴、点、行列、颜色、线、嵌套框、空白分别代表什么？
- 与哪个对照比较？分母和重复单位是什么？
- 怎么从图读出结论？给一个具体位置或基因对作为示例。
- 能说明什么，不能说明什么？
- 图注和 Methods 是否一致？出处为哪一页、哪个 panel？

复杂图拆成“先看坐标 → 看对照 → 看代表性结果 → 总结”，不要只用一句“显著提高”代替读图。

## 展示与交互

- 单文件离线可读，CSS、脚本和图片内嵌；正文不得依赖 CDN、在线字体或在线公式渲染。原文外链可存在，但不影响本地阅读。
- 中文 UTF-8；有目录锚点、清晰层级、图注、表格标题和来源链接；窄屏不横向撑破正文，宽表允许局部滚动。
- 原图清晰可放大，图片支持点击查看大图时应有关闭按钮和 Escape 键；无 JavaScript 时仍能阅读全部重要内容。
- 长方法、完整公式和补充讨论可折叠；主要结论、关键限制不能默认藏在无法发现的位置。
- 区分原文结果、自绘解释、教学例子和本组建议；尽量用明确标签，不只依赖颜色。
- 图像 alt 文本至少说明主题；颜色有文字冗余；浅色底配深色正文。
- 不把整篇 PDF 作为图片塞进 HTML。选择支持论证的 panels，保留署名、出处与版权说明。
- 英文版不逐字硬译，术语准确、句子自然；不得比中文版更肯定因果或临床用途。

## 检查

在浏览器打开并做离线测试，核对目录、图像、放大/关闭、折叠、表格、公式、链接。至少检查桌面与窄屏；提供打印样式，避免打印时图片或表格被无意义截断。若无法做浏览器检查，交付时注明限制，不能声称完整验证。
