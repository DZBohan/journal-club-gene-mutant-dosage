# 流程与证据标准

## 1. 接收与定范围

- 读取仓库 README、AGENTS 与相关日志，确认工作树及用户已有修改。
- 记录原文文件、题目、作者、期刊、年份、DOI、版本和补充材料是否齐全。页码同时标明 PDF 页序与印刷页码，避免混淆。
- 记录受众、语言、时长、交付物、截止时间、与本组工作的已知联系。未提供时声明默认值；不得杜撰组内课题、数据或研究计划。
- 接收的是“解释”请求时不修改文件；接收修改请求时保留批准内容和用户手改版本。

## 2. 先读证据，再写故事

阅读摘要和主图建立地图，再读正文、全部相关 Methods、图注和必要补充材料。不能只凭摘要或截图写方法。

建立 `evidence.csv`，每个重要主张记录原文位置、样本范围、数值、统计方法、限定条件与核查状态。找不到依据就标为未核实，不补造数字。正文、图注和 Methods 不一致时记录冲突，必要时查官方代码或勘误，不能静默选择方便的版本。

证据层级须明确区分：

| 层级 | 要回答的问题 |
|---|---|
| 作者问题与背景 | 哪个知识缺口尚未解决，为什么重要？ |
| 核心工具或实验 | 输入什么，具体做什么，输出什么？ |
| 基准验证 | 真值或参照是什么，如何衡量准确性？ |
| 真实数据应用 | 在哪个队列得到什么结果，能外推多远？ |
| 下游模型 | 使用核心输出做什么新分析，是否换用了另一种方法？ |
| 生物学解释 | 数据直接支持什么，哪些属于作者假说？ |
| 本组应用 | 我们建议检验什么，所需数据和验证是什么？ |

“本组可应用”不能自动写成“已具备临床用途”。数据库注释、患者队列、测序 panel、分析工具分别解释，不能混称为 mutation database。

## 3. 方法必须可被复述

为每一步写四项：输入、操作、输出、为什么需要。第一次出现时定义缩写、变量、单位和统计单位。

特别核查：

- 一行、一列、一个点、一个框各代表样本、基因、基因对、队列还是模拟次数？
- 数据分割服务于估计先验、拟合模型、调参还是测试？训练、验证、测试是否存在样本或患者泄漏？
- 模拟是方法内部的零模型、已知真值的基准数据，还是病例混合的随机对照？三者不得混为一谈。
- 随机化保留哪些约束，打破哪些关系？边际数量是严格保持还是近似保持？
- 输出是计数、加权统计量、概率、效应量、P 值还是 FDR？不能互相替代。
- 同一研究可能先筛 pair，再用 ElasticNet 等下游模型研究结局。必须画出模型边界，不能把所有结果都归于核心工具。
- 负对照是有依据的参照，不是逻辑上绝对无效；特异性、召回率、精确率各用正确分母。
- “验证”说明是独立队列重复、内部交叉验证、参考标注比较还是功能实验。

## 4. 教学例子必须数学可行

自拟数字全部标为 Teaching example / Not study results；假设的背景均值要写明是假设，不冒充模拟所得结果。

- N 个样本中 A 有 a 个、B 有 b 个，重叠 x 必须满足 `max(0,a+b−N) ≤ x ≤ min(a,b)`。例如 N=100、a=b=80 时不能画 x=50。
- 同一例子跨页沿用时，计数、权重、分母、舍入规则一致。若改变场景，明确指出。
- 需要展示保留行计数和列负荷的模拟图，就必须实际核对二者。不能画成均匀分配后声称保留异质性。
- 概率和为 1；集合并集扣除交集；计数非负；平均比值不等于比值的平均；先验均值不一定等于众数。
- 效应量正负代表方向，绝对值代表哪种强度要按论文定义核对。差值、距离、绝对值及颜色分类逐一检查。
- 一个模拟表不代表很多次模拟；重复模拟应画多个表或明确说明“one simulation”。
- 简化图不能删掉正在讲的核心约束。无法直观画对时用文字或更合适的教学例子，不用错误图形凑数。

## 5. 结果组织

每个结果围绕一个问题，采用“问题 → 比较/实验 → 原始 panel → 具体发现 → 含义和边界”。不是顺序粘贴所有主图，也不只列泛泛结论。

至少涵盖对主结论必要的实验、定量结果、阴性/失败结果和适用范围。样本数说明是患者、样本、位点、细胞还是 pair；百分比给出分母；队列间重复和样本内重复区分。

记录关键数值、效应、置信区间或原文不确定性、检验及多重校正。不要从低分辨率图估出精确数字。图谱边不等于分子相互作用、同一克隆或演化时间顺序。

## 6. 组会讨论

默认准备约 20 分钟主讲，备注用时应实际求和。保留本仓库已有可选形式：Student 20 分钟；PI 提前三点问题（48 小时）；PI 提问 10 分钟；Student 回答 10 分钟；实验室讨论与投票 10 至 15 分钟。用户未要求时不自动安排人员、日历或外部消息。

讨论至少包含三类问题：

1. 证据是否足够支持核心结论？关键替代解释是什么？
2. 外部数据、癌种、技术平台或样本来源改变后，还能成立吗？
3. 本组如何做一个可执行的后续检验？具体需要什么数据、对照、测量和成功标准？

## 7. 修订、归档与发布

- 维护疑问与错误记录，区分事实错误、表述歧义、设计问题。
- 发现错误不能只在聊天里解释。已获修改授权的版本同步修复图、正文、备注、双语版本及导出；若当前只问解释，记录已知问题并说明旧文件仍未修复，不擅自覆盖。
- 用户认可的结构、完整图例和连续例子不得为追求简洁而删除。新增示意图是补充，不自动替换已批准内容。
- 每次交付声明修订范围、版本、检查结果、未解决项；保留用户修改，不把旧草稿称为最终版。
- 提交仅包含本次相关文件。push 需要当次授权；用户明确要求 push 时可执行普通推送，不能 force push。失败如实报告。
